# AI-Team

Current application version: **0.24**. See [About](documentation/ABOUT.md), the [version log](documentation/VERSIONS.md), and the [full project documentation](documentation/DOCUMENTATION.md).

The web client is served from `static/` (`index.html`, `app.js`, and `style.css`). The server keeps application data and logs under `TEAM_DATA_DIR` (default: `data/`).

Settings are organized into Projects, Connections, Routing, Logs, and About tabs. Statistics remain available from the main header.

In **Settings → Logs**, **Store from** sets the minimum level written to the rotating log files and persists across restarts. **Show** filters the most recent matching entries in the log viewer. The **Documentation** button browses the local `documentation/` folder; **Files** browses the active project's configured local clone.

Git clone runs as a background job so a slow network fetch does not hold the browser request open. Progress and Git's final error output are written to `logs/app.log`; the project editor polls the job and displays the actual failure message. A failed clone is staged in a temporary sibling folder and removed, so retrying does not fail because of a partial destination. The Git status endpoint is also available as `GET /api/git/{project_id}/status`; it returns `Not cloned yet` before a local checkout exists.

For the supplied systemd service, project clone paths may be placed under `/home/ubuntu/projects`; the service unit grants write access to that workspace while keeping the rest of `/home` read-only and the rest of the OS protected. The service still runs as the unprivileged `ubuntu` user, so normal Unix ownership and permissions apply. Create the workspace if needed with `sudo install -d -o ubuntu -g ubuntu -m 0750 /home/ubuntu/projects`. After installing an updated `personal-ai-team.service`, run `sudo systemctl daemon-reload` and `sudo systemctl restart personal-ai-team`. Ensure the workspace is writable by `ubuntu` (for example, check with `sudo -u ubuntu test -w /home/ubuntu/projects`). Do not run the app as root or grant it write access to the entire filesystem.

Permission errors when checking or creating a clone are returned as actionable messages and logged, rather than as an unhandled server error. The local Files browser is read-only; filesystem write/delete capabilities are currently used by Git clone/pull/push, and changing systemd access alone does not add a general file editor or deletion UI.

**App Update** uses the configured GitHub repository credential from **Connections**. Set **Local repository checkout directory** to a writable path for the service user (for example, `/home/ubuntu/projects/personal-ai-team-update`). The updater clones there on first use and fast-forward pulls on later updates, then copies files into the configured **App working directory**. For each file, the newer modification time wins; repository `.git`, virtual environments, caches, and dependency directories are not copied, and deployment-only files are never deleted. The checkout and working directories must be separate, non-overlapping paths.

The supplied service unit explicitly allows writes to `/opt/personal-ai-team`, but that grant applies only after the updated unit is installed and the service is restarted. If an update reports `Read-only file system`, the active systemd sandbox does not yet include the grant; `chmod`/`chown` alone will not resolve it. Install the updated unit at `/etc/systemd/system/personal-ai-team.service`, then run `sudo systemctl daemon-reload` and `sudo systemctl restart personal-ai-team` before retrying. Verify the active configuration with `sudo systemctl show personal-ai-team -p ProtectSystem -p ReadWritePaths`; it should show `/opt/personal-ai-team` in `ReadWritePaths`. Unix ownership still applies too, so ensure `ubuntu` has write access to the deployment directory and any configured checkout path. The updater sends its response, then exits the service process; systemd's `Restart=always` policy brings it back without granting the app sudo/root privileges. The browser waits for the service to return before reloading.
