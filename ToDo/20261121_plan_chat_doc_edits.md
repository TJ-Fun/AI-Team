# Plan: Chat-driven project document edits + remove Plan button

## Goal
Let the user discuss document changes with the PM/PO in chat, say "proceed", and have the PM create a `doc_edit` task that updates any subset of: `roadmap`, `phase_1`–`phase_9`, `project_brief`, `technical_overview`, `decisions`, `outcomes` (optional `active_phase`). `project_vision` and `*_tracker` docs stay read-only. Changes always land in **Needs approval** before being applied. Remove the confusing "Plan" chat button and `/api/pm-requests` endpoint.

## Design
- New task type `doc_edit` reuses the existing update pipeline: contract → parse → `update_payload` → **Needs approval** → `decide_doc_update` → `apply_doc_update` (versioned snapshots already built in).
- Chat side-channel mirrors `info_requests`: PM may reply with a JSON-only object `{"doc_edit_request":{"message":"...","request":"...","documents":[...]}}`. Backend creates the task, posts a chat notice, and shows `message` as the reply.

## Batch 1 — Backend: doc_edit task type
- `ait/common.py`: add `PROJECT_DOCS_UPDATE_CONTRACT` — JSON `{"type":"doc_edit","summary","documents":{slug: full Markdown},"active_phase":int|null}`; only changed docs, full text each, ≤20k chars, never `project_vision`/trackers; use `info_requests` to fetch current docs first.
- `ait/doc_updates.py`:
  - `DOC_EDIT_ALLOWED_SLUGS` = 4 core docs + `roadmap` + `phase_[1-9]` (validated via regex, not `is_project_doc_slug` — excludes vision/trackers/legacy).
  - `parse_doc_edit_response(reply)` — require `type=="doc_edit"`, non-empty `documents` dict, every slug allowed, each text non-empty ≤ `MAX_DOC_CHARS`, optional `active_phase` int 1–9.
  - `finish_doc_edit_task` via existing `_finish_update_task`.
  - `apply_doc_update`: handle `doc_edit` — save each `documents` slug + `active_phase` (same logic as `roadmap_update` branch).
  - Add `"doc_edit"` to `DOC_UPDATE_TASK_TYPES`.
  - `create_doc_edit_task(project_id, request, documents)` — builds Ready task (assigned PM/PO, `DISPATCH_EVENT.set()`), composed request text listing target docs + agreed change.
- `ait/qa_review.py`: `planning_contract_for_task` → `doc_edit` returns new contract.
- `ait/provider_dispatch.py`: finish branch `doc_edit` → `finish_doc_edit_task`.
- *App stays functional; type is inert until Batch 2.*

## Batch 2 — Backend: chat action + task creation
- `ait/info_requests.py` (or new `ait/chat_actions.py` if cleaner): `extract_doc_edit_request(reply)` — JSON-only parse, validate `request` non-empty ≤4000 chars, `documents` optional list filtered to allowed slugs, `message` optional ≤2000 chars.
- `ait/chat.py`: extend `chat_system_prompt` — document the `doc_edit_request` JSON, when to emit it (only after explicit user confirmation), scope limits, and that the task still requires user approval before applying.
- `ait/http_handler.py` POST `/api/chat`: after `call_chat_provider`, run extractor; on hit → `create_doc_edit_task`, `append_chat_notice` with task id, replace displayed reply content with `message` (+ task reference), include `task_id` in response.
- Commit + push.

## Batch 3 — Frontend: remove Plan, render doc_edit
- `static/index.html`: remove `#plan-request` button; update `.chat-notice` text (drop "Use Plan…", mention PM can queue document updates after you confirm).
- `static/js/chat.js`: remove `plan-request` listener.
- `ait/routes_tasks_pm.py`: remove `/api/pm-requests` block (endpoint only used by Plan button; `pm_planning` task type stays for internal clarification follow-ups).
- `static/js/task-detail.js`: add `"doc_edit"` to provider-row exclusion list and `isUpdateTask` list; extend `active_phase` meta condition to include `doc_edit` (generic `documents` map already renders).
- `static/js/task-detail-actions.js`: add `"doc_edit"` to approve/reject list.
- `static/js/task-copy.js`: verify/add `doc_edit` payload rendering.
- Commit + push.

## Batch 4 — Docs, version, final commit
- Update `documentation/DOCUMENTATION.md` (chat actions, doc_edit flow, removed Plan) and `documentation/VERSIONS.md` (increment).
- Final commit + push.

## Impact analysis
- `pm_planning` task type and `finish_pm_planning_task` remain (clarification follow-ups in `routes_tasks_pm.py` answer flow, `env_tasks.py`, `release_publish.py`).
- `doc_update`/`roadmap_update`/`vision_update`/`board_delta` untouched; `doc_edit` is additive.
- Trackers (`roadmap_tracker`, `phase_N_tracker`) are auto-generated by `sync_project_trackers` — excluded from edit scope by slug whitelist.
- Chat replies that aren't valid `doc_edit_request` JSON display unchanged (fallback = normal text).
